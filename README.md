# mculib

分层 MCU 驱动框架。

## 零、信任前提

mculib 假定使用者具备嵌入式开发能力，并会严格遵守契约中规定的上下文、并发、生命周期、回调限制。

框架不提供运行时的违约检测、保护、降级、恢复机制。
框架不为了防错而引入额外的类型、状态机、间接层或运行时开销。

契约中的“必须”“禁止”“不得”是使用条件，不是建议。
违反条件的后果由使用者承担。

在此前提下：

- 回调可以在 ISR 内直接执行；
- 参数检查仅在 Debug 构建保留；
- 不提供双重模式、逃生舱标记、运行时状态校验；
- 适配层路径最短，开销最低。

## 一、分层与依赖方向

```
app/         应用层：inc/ 导出头文件，src/ 实现
subsystems/  子系统层：API 契约（纯头文件）
common/      工具层：跨子系统通用能力（纯头文件）
adapter/     适配层：唯一接触厂商 API / 低层 API / 寄存器的地方，按后端分目录，每个后端 inc/ + src/
board/       板级：设备实例与资源绑定，inc/ 导出头文件，src/ 实现
config/      后端选择：单一开关（纯头文件）
tools/       构建辅助脚本
```

依赖只能向下，禁止反向：

```
app    → subsystems
app    → common
app    → board
board  → adapter
board  → config
common → adapter
adapter → config
adapter → 厂商 API / 寄存器
```

- `subsystems/` 与 `common/` 平级，互不依赖。
- 子系统层不出现芯片类型、不包含 `adapter/` 或 `config/`。
- 工具层不出现芯片类型、不包含 `subsystems/`。
- 适配层不依赖应用层与板级。
- 应用层不包含适配层与芯片头文件。
- 目录约定：凡同时含 `.h` 与 `.c` 的层，一律分 `inc/`（导出头文件）与 `src/`（实现）；纯头文件层（`common/`、`subsystems/`、`config/`）保持扁平。层一旦出现 `.c`，整体转为 `inc/` + `src/`，不混放。
- 头文件包含一律写仓库根起的完整路径，含层内目录：`#include "app/inc/sbus.h"`、`#include "board/inc/board.h"`、`#include "subsystems/subsystems_uart.h"`；构建因此只需 `-I.`。

## 二、各层职责

| 层 | 必须 | 禁止 |
|---|---|---|
| 应用层 | 只调用子系统 API、工具 API 与板级导出的实例 | 包含适配层 / 芯片头文件；直接操作寄存器 |
| 子系统层 | 定义动词化 API 契约；只包含标准头文件 | 芯片特定类型；为未使用的功能预留 API；依赖工具层 |
| 工具层 | 提供跨子系统通用能力；纯逻辑实现不依赖芯片；硬件相关部分由适配层实现 | 外设契约；业务逻辑；依赖子系统层 |
| 适配层 | 硬件原子操作映射；通过设备私有指针访问数据 | 做策略（缓冲、重试、流控）；做板级选择；包含应用逻辑 |
| 板级 | 实例化设备、绑定资源、导出实例、显式初始化 | 逻辑（业务判断、循环）；同一资源多处定义 |
| 配置层 | 只做后端选择 | 被子系统层或工具层包含；宏定义散落到别处 |

## 三、新增一个子系统

1. **契约**：`subsystems/<子系统>.h`
   - 只包含标准头文件。
   - API 动词化、直接表达硬件语义：`<子系统>_<动作>`。
   - 错误码统一：`0` 成功，负值失败。
   - 超时单位统一毫秒，`0` 表示非阻塞。
   - 定义该子系统自己的设备结构体，持有私有指针或底层句柄。
   - 声明默认线程安全：同一设备上的并发调用由适配层串行化。
   - 回调必须写明上下文与限制。
   - 异步接收以数据包为单位时，使用空闲中断作为帧边界，回调携带实际长度与错误位，不使用链式缓冲区。
   - 发送类异步 API 只提供完成通知，不引入额外状态机。
   - 中断触发方式等一次性硬件属性由板级初始化固定，运行时不可变。
2. **实现**：`adapter/<后端>/src/<子系统>_<后端>.c`，导出头文件 `adapter/<后端>/inc/<子系统>_<后端>.h`
   - 文件头部包含 `config/backend.h`，全部实现用 `#if` 守卫包住，未选中时展开为空。
   - 通过设备结构体的私有指针访问私有数据。
   - 按操作类型选底层：配置/初始化走厂商高层 API；极短操作与热路径用低层 API 或寄存器；中断内不清标志以外的多层封装。
   - 不做策略、不做板级选择。
3. **板级**：在 `board/src/board.c` 实例化设备结构体、绑定资源，在 `board/inc/board.h` 导出实例，并提供显式的初始化函数。
4. **应用**：只调用子系统 API 与板级实例。

## 四、新增一个外设实例

同一子系统有多个实例时：

- 在板级再加一个设备结构体实例与对应的资源绑定。
- **不**新增 API，**不**改子系统头文件。
- 一个硬件资源只在一处出现。

## 五、新增一个后端

1. 建立 `adapter/<新后端>/inc/` 与 `adapter/<新后端>/src/`，按后端名实现各子系统 API；可以先复制现有后端目录作为参照。
2. 在 `config/backend.h` 勾选新后端，其余保持注释。
3. 把板级文件换成绑定新后端的版本。

约定：

- 后端开关只在 `config/backend.h` 一处，一次只能勾选一个。
- 构建系统编译 `adapter/*/src/*.c`（`adapter/` 下**所有**后端源文件），未选中的由守卫展开为空，因此同一二进制不会含两个后端。后端目录漏建 `src/` 会被通配静默跳过，只在链接期报未定义符号。
- **一份板级文件对应一个后端**：写死它使用的后端头文件与绑定调用，不做 `#if` 选择；换板 = 换一份板级文件。
- 板级文件写死的后端必须与 `config/backend.h` 勾选的一致，不一致不会编译报错，只会在链接期报未定义符号。

## 六、设备结构体

- 每个子系统定义自己的设备结构体，持有私有指针或底层句柄。
- 不引入统一设备基类，不与子系统无关的字段混在一起。
- 单后端场景直接由适配层实现子系统 API，**不引入 ops 表**。
- 确实需要 ops 表时，用 `_Static_assert` 检查函数指针非空。
- 工具层不定义设备结构体。

## 七、并发与中断

- 并发在驱动内部处理。短操作可用互斥量或临界区；长流程或复杂状态机可在适配层内部引入服务任务 + 静态队列。
- 队列消息使用静态池，避免动态分配。
- 中断内只做清标志、取数据、调用回调。
- 回调在 ISR 内执行时，必须只做轻量级置位，不得阻塞、不得加锁、不得等待、不得调用子系统 API。
- 若回调需要处理数据，由使用者自行拷贝或置位后由任务处理。
- 下半部机制为可选项，由使用者在需要时自行实现。
- 无原生原子指令时，降级为关中断临界区。
- 中断上下文只允许非阻塞提交。

## 八、生命周期

- 只有三段：定义（编译期）→ 初始化（启动时）→ 使用（运行时）。
- 需要启停语义用专用 API（`start` / `enable`）；需要互斥、挂载或上电用明确命名（`acquire` / `release` / `power_on` / `power_off`）。
- 不引入 open/close、运行时设备注册、热插拔、通用生命周期管理。

## 九、性能

- 关键路径可绕过框架直接操作寄存器。
- 配置类用厂商高层 API，热路径用低层 API 或寄存器。
- 不在热路径引入间接调用（ops 表）。
- 不为了“薄”重写厂商已正确实现的复杂配置逻辑。
- 发布构建裁掉参数检查与断言。
- 工具层提供零开销或低开销的通用能力，不引入运行时状态机。

## 十、工具层

`common/` 提供跨子系统通用能力，与 `subsystems/` 平级。

- 纯逻辑工具：位操作、通用宏、编译期断言、环形缓冲区、字节序、软件 CRC。只包含标准头文件，实现放 `common/*.c`（`common/` 现为纯头文件层，一旦出现 `.c` 即转为 `common/inc/` + `common/src/`）。
- 硬件相关工具：临界区、延时、原子操作、系统时间、日志、看门狗、复位、唯一 ID。契约放 `common/`，实现放 `adapter/<后端>/`。
- 工具层不提供读-改-写宏，避免隐藏并发风险。
- 需要硬件加速的工具（如 CRC）由适配层在编译期选择硬件或软件实现；硬件不支持给定参数时自动回退软件实现，两者输出必须一致。
- 不提供运行时错误降级；硬件与软件选择在编译期完成。
- 工具层不预留未使用的 API，按实际使用场景逐项加入。

## 十一、构建

```sh
make          # 构建，产物在 build/Debug/
make run      # 运行
make compdb   # 只刷新编译数据库
make clean    # 删除 build/
```

- 新增源文件无需改构建脚本（源文件按目录通配：`app/src/`、`board/src/`、`adapter/*/src/`、`common/`、`subsystems/`）。
- 头文件一律从仓库根写完整路径（含层内 `inc/`），故编译开关只需 `-I.`。
- `make` 会生成 `build/Debug/compile_commands.json`，并维护软链接 `build/compile_commands.json` 供 clangd 使用。

## 十二、明确不采用

设备树、Kconfig、统一设备基类、编译期自动注册段、统一 `read/write/ioctl`、`open/close`、运行时设备注册与热插拔、用户空间隔离、sysfs、Runtime PM、复杂中断路由树、DMA 描述符链与分散聚集、共享中断、中断线程化、链式接收缓冲区、双重回调模式、运行时状态校验、运行时错误降级。
